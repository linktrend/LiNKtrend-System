## Trajectory / debug

- `supabase/migrations/` did not exist on `development`, so LTS-020 creates the canonical Supabase migration directory for this issue.
- The migration deliberately avoids foreign keys to tenant/project/run tables because LTS-001 is in the same first wave; later integration can add foreign keys after the kernel schema lands.
- The write path uses RPC functions (`record_mvo_audit_event`, `record_mvo_memory_object`) and tenant-scoped RLS select policies, matching the security rule that Supabase writes go through functions rather than direct table mutation.
